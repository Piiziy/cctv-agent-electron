# 시연 영상

`/wanted-test` 실서버 시연에서 **CCTV 대신 쓰는 영상**을 여기에 넣는다. 영상 하나가 카메라 한 대다.

```
public/demo-video/01-계산대.mp4   → 카메라 이름 '계산대'
public/demo-video/02-출입문.mp4   → 카메라 이름 '출입문'
```

- 앞의 번호는 순서만 정하고 이름에서는 빠진다. **파일 이름을 바꾸면 서버에서 다른 카메라가 된다**
  (카메라 id 가 파일 이름에서 나온다).
- mp4 · mov · m4v · mkv · webm · avi 를 받는다.
- 넣고 `main` 에 올리면 Vercel 빌드가 알아서 자른다. 손으로 할 일은 없다.

## 빌드가 하는 일

`apps/demo-web/scripts/demo-video.mjs` 가 매장 PC 에이전트와 같은 모양으로 미리 잘라 둔다.

| | 기본값 | 바꾸려면 |
|---|---|---|
| 조각 길이 | 30초 | `DEMO_SEGMENT_SECONDS` (30 · 60 · 300 중 하나 — 매장 설정 값과 같아야 한다) |
| 화질 | 세로 480 (원본보다 키우지 않음) | `DEMO_VIDEO_HEIGHT` |
| 초당 프레임 | 원본 그대로 (30 이 넘으면 30) | `DEMO_VIDEO_FPS` |
| 소리 | 뺀다 | — |

화질을 낮춘 이유: 서버 AI(YOLO 포즈)는 어차피 긴 변 640 으로 줄여서 본다. 480p 면 충분하고 파일이 작다.

프레임은 낮추지 않는다. AI 는 한 사람을 **연속 32프레임**씩 묶어 보는데, 15fps 로 떨어뜨리면 그 묶음이
2초가 넘어 짧게 튀는 동작이 묻히고 추적이 한 번만 끊겨도 묶음이 안 생긴다. 지금 영상도 25fps 로는 매번
'높음'인데 15fps 로는 '보통'에 그쳤다. 대신 fps 만큼 분석이 오래 걸린다 (26초 · 25fps 조각 = 650프레임,
데스크톱 CPU 로 포즈 뽑기 약 30초).

로컬에서 미리 잘라 보기:

```bash
node apps/demo-web/scripts/demo-video.mjs
```

## 영상 고를 때

서버 AI 는 **조각 하나 안에서** 유독 튀는 움직임을 위험으로 본다 (조각마다 따로 학습한다).
사람마다 연속 32프레임 묶음의 자세를 복원해 보고, 복원이 유독 안 되는 묶음(평균 + 2.5 표준편차 초과)을 표시한다.
위험도는 그 점수가 기준의 몇 배인지다 — 1.5배 이상 '높음', 1.2배 이상 '보통'. **PC 경고창은 '높음'에만 뜬다.**

- 사람이 몸 전체가 보이게, 오래 끊기지 않고 잡혀야 한다. 흑백 · 어두움 · 두건 · 화면 가장자리에 걸친 사람은
  추적이 자주 끊겨 묶음이 거의 안 생긴다 (예전 영상은 21초 동안 묶음이 0개였다).
- 이상 행동은 **짧게**, 나머지는 평범한 움직임이 **길게** 있어야 '높음'까지 간다. 튀는 묶음이 몇 개만 있어도
  평균·표준편차가 같이 올라가서 배율이 금방 1.2~1.4 에 머문다. 사람이 넘어져 계속 누워 있는 장면도 그래서 약하다.
- 조각 경계(30초 · 60초 …)에 걸치지 않게 둔다.
- 영상 파일은 배포에 그대로 실려 **누구나 받을 수 있다**. 공개해도 되는 영상만 넣는다.

**넣기 전에 AI 로 돌려 본다.** 잘린 조각(`apps/demo-web/.generated/demo-video/*/seg-000.mp4`)을
백엔드 `ai-worker` 의 `pipeline.report.process_video` 에 넣으면 워커와 똑같이 판정한다. 학습에 시드가 없으니
몇 번 돌려서 매번 1.5배를 넘는지 본다.

연출 영상이라 실제 인물 촬영물의 초상권 문제가 없다. 매장이 아니라 서버실이다 — 무료 영상 중 CCTV 시점으로
매장 안 사건을 찍은 것 가운데 AI 가 '높음'으로 잡는 영상을 찾지 못했다.

AI 판정 (서버와 같은 파이프라인 · 이 조각 그대로 · 학습 시드 10가지, 2026-09-19): 매번 **3.8~5.3초**
(카메라를 건드린 사람이 서버 쪽으로 돌아서는 순간)를 **1.86~1.93배 '높음'** 으로 잡는다. 하이라이트 클립은
앞뒤 5초를 붙여 0~10초 — 카메라를 가리는 장면이 들어간다. 백엔드 `fix/ai-worker-torchvision-cpu` 의 두 수정
(torchvision · 가려진 keypoint)이 배포돼 있어야 한다. 수정 전 AI 로는 같은 영상이 1.0배 안팎이다.
