# 클로드 코드에 줄 프롬프트 가이드

## 준비: 넘겨줄 파일 (이 프로젝트에서 "다운로드"로 받아 레포에 넣기)
```
design/
  씬스틸러 디자인시스템.dc.html   ← 토큰·타이포·컴포넌트 규칙 (단일 출처)
  씬스틸러 PC 앱.dc.html          ← PC 7화면 하이파이 (2a–2g)
  CCTV 위험감시 UX 뼈대.html      ← 뼈대 + 손글씨 주석(왜 이렇게), 모바일 2i–2m 포함
  ds/fig-tokens.css               ← 피그마 변수 94개 (CSS 변수, light/dark)
  ds/fig-typography.css
  ds/assets/                      ← 로고·아이콘 SVG
  씬스틸러 디자인시스템.fig        ← 모바일 확정 디자인 (Gui 페이지 프레임들)
  handoff/API-요구사항.md
```
HTML은 브라우저로 열어 보게 하면 되고, 클로드 코드는 소스를 직접 읽습니다 (`.dc.html` 안 인라인 스타일이 정확한 값).

---

## 프롬프트 원칙 (공통)
1. **한 세션 = 한 화면(또는 한 컴포넌트 묶음)**. 7화면을 한 번에 시키면 품질이 떨어짐.
2. **순서**: ① 토큰/공통 컴포넌트 → ② 레이아웃 셸(내비·라우팅) → ③ 화면 하나씩 → ④ 실시간/푸시 연결.
3. 매 프롬프트에 **"디자인 파일 경로 + 화면 ID + 값을 그대로 쓸 것"**을 반복 명시. 클로드 코드는 컨텍스트가 새로 시작되므로 매번 짚어줘야 함.
4. **"임의로 색·간격·반경 바꾸지 말 것, 없는 값은 디자인시스템 파일에서 고르고 그 이유를 한 줄 남길 것"** — 이 한 문장이 결과 품질을 가장 많이 좌우함.
5. 완료 기준을 프롬프트에 적기: "브라우저로 열어 디자인 HTML과 나란히 비교, 다른 점 목록으로 보고".

## 1단계 — PC 앱 (Electron, 기존 cctv-agent 레포)

### 프롬프트 1-0: 디자인 시스템 이식
```
너는 cctv-agent (Electron + React + Tailwind) 프론트를 리디자인한다.
디자인 단일 출처: design/씬스틸러 디자인시스템.dc.html, design/ds/fig-tokens.css.

할 일:
1. design/ds/fig-tokens.css 를 src/renderer/styles 에 넣고 Tailwind 설정을 이 CSS 변수로 매핑
   (gray 50–900, blue 50–900, error, success, brand main #14233D, sub #3B6FF5,
    risk/high #E01F12, risk/medium #F9A403, risk/low #868B94).
2. 폰트: Pretendard (본문) + Prompt 700 (로고 워드마크만). 전역 letter-spacing -0.01em, tabular-nums.
3. src/renderer/components/ui.tsx 를 디자인시스템 4장 '컴포넌트' 기준으로 교체:
   Button(primary navy r12 / action blue r8 / secondary outline / danger / loading / link),
   Input(48px, r12, default·focus·error·done 4상태), Tag(r99, 위험도·상태 색), StatusDot,
   Toggle(44×24), Segmented, Pagination, Card(r12, shadow 2px 4px 20px rgba(0,0,0,.04)),
   CameraTile, RiskCard, TopNav(높이 76, 로고+메뉴 4개+매장선택 칩+사용자+로그아웃).
4. 디자인 HTML의 값을 그대로 쓴다. 반경·색·간격·크기를 임의로 바꾸지 않는다.
   디자인에 없는 상태(hover/disabled 등)가 필요하면 같은 팔레트에서 고르고 코드 주석으로 이유를 남긴다.
5. 완료: Storybook 없이도 확인할 수 있게 /dev/components 라우트에 모든 컴포넌트 상태를 나열해라.
```

```
- 페이지 배경 #F7F8F9, 좌우 여백 40px, 카드 간 16px

- 위험 팝업(2d)은 라우트가 아니라 어느 화면 위에서든 뜨는 always-on-top 모달 (Electron BrowserWindow alwaysOnTop + 포커스)
기존 App.tsx 의 서버설정→카메라선택→대시보드 흐름은 2a→2b→2c 로 대체한다. 서버 주소/토큰 입력은 /settings/advanced 로 이동.
```

### 프롬프트 1-2 ~ 1-8: 화면 하나씩 (템플릿)
```
design/씬스틸러 PC 앱.dc.html 에서 id 배지 "2c" 화면(실시간 대시보드)을 구현한다.
참고: design/CCTV 위험감시 UX 뼈대.html 의 2c 손글씨 주석(왜 이렇게 만들었는지)도 읽어라.

레이아웃·값은 디자인 HTML 소스의 인라인 스타일을 그대로 쓴다 (1440 기준, 창 크기에 따라 카드 격자만 반응형).
상태:
- 카메라 타일: 연결됨 / 재연결 중(마지막 프레임 + 경과시간, error/300 테두리) / 끊김 / 빈 슬롯(+추가, 8대 제한)
- 우측 '오늘 위험 신호' 피드: 필터 칩(전체/미확인/높음만), 카드 4종(높음-테두리 error/600·배경 error/50, 보통, 확인됨 opacity .6, 오탐 취소선)
- 상단 상태: 감시 중 N/M대, 서버 전송, 마지막 분석 시각, '일시 중지(영업 중)' 버튼
데이터: 우선 mock (src/renderer/mock/*.ts) 로 만들고, API 연결 지점은 hooks 로 분리 (useCameras, useTodayEvents). 실제 엔드포인트는 handoff/API-요구사항.md 2.2·2.5·4.3 을 백엔드에서 받아 붙인다.
완료: 앱을 띄워 디자인 HTML과 나란히 스크린샷 비교, 차이점 목록 보고. 임의로 디자인을 바꿨다면 이유 명시.
```
같은 템플릿으로 2a, 2b, 2d, 2e, 2f, 2g 를 순서대로. 화면별로 꼭 짚을 점:
- **2b**: 3단계 위저드, 좌우 패널 opacity .55로 비활성 표현. 기존 CameraSelect/CameraSetup 로직(ONVIF 검색, probe, 프로필)을 재사용하고 UI만 교체. '조각 길이'는 UI에서 '알림 빠르기'로, 기본 1분.
- **2d**: alwaysOnTop 창, 소리, 클립 자동 반복재생, 바운딩박스 오버레이, 확인/오탐 버튼 시각 분리, ✕ = 미확인 유지. 확인 안 하면 5분 후 재알림은 서버 책임(6.5).
- **2e**: 타임라인(카메라별 행, 위험도 색, 영상 없음 점선) + 테이블 + 우측 미리보기 3분할. 행 클릭 → 미리보기, 더블클릭 → 2f.
- **2f**: 조각 단위 타임라인 좌우 이동, 4분할 동시각 카메라 클릭 시 메인과 교체, 드래그로 내보낼 범위 선택, 증거 묶음 내보내기는 비동기 작업 진행률 표시.
- **2g**: 토글/세그먼트 변경 즉시 저장(저장 버튼 없음), 쓰러짐 항상 on(disabled 토글).

## 2단계 — 모바일 앱 (React Native 또는 Flutter, 새 레포)

모바일은 **피그마가 확정 디자인**, 뼈대 HTML은 **화면 구성·기능 근거**. 둘의 관계를 첫 프롬프트에서 명확히.

### 프롬프트 2-0: 피그마 → 토큰/컴포넌트
```
새 모바일 앱(RN + TypeScript, Expo)을 만든다. 디자인 출처:
- 피그마 design/씬스틸러 디자인시스템.fig — 'Gui' 페이지 프레임이 확정 모바일 디자인. Figma MCP(또는 내보낸 PNG + 값 표)로 프레임을 읽어라.
- 토큰: design/ds/fig-tokens.css 와 동일 값 (gray/blue/error/success, brand #14233D / #3B6FF5). PC와 같은 팔레트를 써야 한다.
- 화면 구성·기능·인터랙션 근거: design/CCTV 위험감시 UX 뼈대.html 의 2i–2m (푸시 / 알림 상세 / 홈 / 기록 / 설정) 및 그 손글씨 주석.
피그마 프레임과 뼈대가 다르면: 시각(색·타이포·간격·컴포넌트 모양)은 피그마, 화면에 들어갈 정보·버튼·흐름은 뼈대를 따른다. 충돌 지점은 목록으로 보고하고 진행.
먼저 theme.ts(토큰) + 공통 컴포넌트(Button, Tag, RiskCard, StatusChip, ListRow, TabBar)를 피그마 값으로 만든다.
```

### 프롬프트 2-1 ~ 2-5: 화면 (템플릿)
```
뼈대 2j '알림 상세·대응' 화면을 구현한다 (design/CCTV 위험감시 UX 뼈대.html 2j + 주석 참고).
시각은 피그마 Gui 페이지의 대응 프레임을 따르고, 없는 요소는 2-0에서 만든 컴포넌트로 조합한다.
필수 요소·동작:
- 상단 클립 자동 반복재생(탭 → 전체화면 가로), 위험 구간 표시 바
- 종류 태그 + 위험도 + 카메라·시각·길이, AI 설명(인상착의 포함)
- 버튼 순서 고정: [112 전화하기(danger, 크게)] → [전후 영상 | 다른 카메라] → [클립 저장·공유(OS 공유시트)] → 구분선 → [문제 없음(오탐) | 확인했어요]
- 112: tel: 다이얼러 실행 + 통화 중 볼 수 있는 정보 카드(매장 주소·시각·인상착의) 오버레이
- 확인/오탐은 API 4.6, 결과는 PC와 동기
- 모바일엔 실시간 영상 없음 — 라이브 관련 UI를 넣지 말 것
완료: 시뮬레이터 스크린샷을 피그마 프레임과 비교, 차이 보고.
```
화면별 핵심:
- **2i 푸시**: 리치 푸시(썸네일) + 액션 2개(클립 보기 / 112), 탭 → 2j 딥링크, 높음/응급은 critical alert 권한 요청. 시스템 알림(카메라 끊김·PC 꺼짐)도 같은 채널.
- **2k 홈**: 매장 칩(여러 매장, 문제 매장 빨간 점) → 상태 카드("감시 중 4/5대", 끊긴 카메라 경고, 마지막 분석) → 오늘 위험 신호(미확인 우선) → 카메라 상태 칩. 탭바 3개: 홈 / 기록(배지) / 설정 (실시간 탭 없음).
- **2l 기록**: 필터 칩, 날짜 그룹, 미확인 상단, 영상 없음 구간 행 삽입, 행 좌 스와이프 → 확인/오탐, 주간 요약 카드.
- **2m 설정**: 알림(종류별·방해금지·응급 무시·테스트) / 내 매장(PC 상태 포함) / 매장 상세(주소·운영시간·카메라 이름) / PC 연결(QR 스캐너 → API 1.5). 카메라 추가는 PC에서만이라는 안내.

### 프롬프트 2-6: 푸시 연결
```
FCM/APNs 등록(API 6.1), 포그라운드/백그라운드/종료 상태 각각에서 2i → 2j 딥링크 검증.
높음 미확인 5분 재알림은 서버가 보내므로 클라이언트는 중복 표시만 방지.
```

## 프롬프트에 항상 붙일 꼬리말
```
규칙:
- 디자인 파일 값을 그대로 쓴다. 색·반경·간격·폰트 크기를 임의로 바꾸지 않는다.
- 디자인에 없는 것이 필요하면 design/씬스틸러 디자인시스템.dc.html 안에서 고르고, 코드 주석에 한 줄 이유를 남긴다.
- 화면 안 텍스트(한글 카피)는 디자인 그대로. 용어: '알림 빠르기'(조각 길이 아님), '확인했어요', '문제 없음(오탐)', '위험 신호'.
- 끝나면 구현 화면과 디자인을 나란히 비교한 차이점 목록을 보고한다.
```
