# 필요한 API 기능 목록 (명세 아님 — 백엔드 담당자가 기존 API에 매핑용)

기준: 확정 UX 뼈대(PC 2a–2g, 모바일 2i–2m) + 기존 `cctv-agent`의 `/v1/segments` 업로드 규격.
각 항목 = "어떤 화면이 · 무엇을 · 왜" 필요로 하는지. 이미 있으면 그대로 매핑, 없으면 추가.

## 0. 공통 개념
- 계정(사장님) 1 : 매장 N : 매장당 PC 1 : 카메라 ≤ 8
- 위험 이벤트 = AI가 판정한 (카메라, 시작~끝 시각, 종류, 위험도, 설명, 클립)
- 이벤트 상태: `미확인 → 확인됨 | 오탐` — PC/모바일 어디서 바꿔도 양쪽 동기
- 위험도: `높음 / 보통 / 낮음` — 종류별 기본값 있고 매장 설정으로 덮어씀
- 위험 종류(7): 절도(미결제 반출) · 기물파손/폭력 · 취식 후 미결제 · 미성년자 주류/담배 · 장시간 배회 · 노숙/취침 · 쓰러짐(응급, 끌 수 없음)

| # | 기능 | 쓰는 곳 |
|---|---|---|
| 1.1 | 휴대폰 번호 인증(코드 발송/검증) → 로그인 토큰 발급 | PC 2a, 모바일 |
| 1.2 | 내 매장 목록 (이름, 카메라 수, 연결된 PC 유무/기기ID) | PC 2a 매장 선택, 모바일 2k 칩·2m |
| 1.3 | 매장 생성 / 이름·주소(112 신고용)·운영시간 수정 | PC 2a "+ 새 매장", 2g, 모바일 2m |
| 1.4 | PC(수집기)를 매장에 연결 — 기기ID 등록·교체(기존 PC 있으면 교체 확인) → 기기 토큰 발급 | PC 2a |
| 1.5 | QR 페어링: PC가 1회용 페어링 코드 생성 → 모바일이 코드로 승인 → PC가 자동 로그인·매장 선택 | PC 2a QR, 모바일 2m "PC 연결" |

## 2. 카메라  (PC 2b · 2c · 2g 카메라관리 · 모바일 2k 상태칩)
| # | 기능 | 비고 |
|---|---|---|
| 2.1 | 카메라 등록 (이름, 위치태그, IP/RTSP, 화질 프로필, 자격증명은 PC 로컬만) → 서버 카메라ID | 2b ③ "감시 시작". 위치태그(계산대/출입문/진열대/취식대/창고/기타)는 AI 컨텍스트로 서버가 씀 |
| 2.2 | 카메라 목록 (매장별, 이름·태그·순서·상태) | 2c 격자, 2f 동시각 카메라, 모바일 2k |
| 2.3 | 카메라 수정(이름·태그·순서) / 삭제 | 2g 카메라 관리, 모바일 2m 이름 변경 |
| 2.4 | 카메라 런타임 상태 보고 (PC → 서버): 연결됨/재연결중/끊김/인증실패, 마지막 프레임 시각 | 모바일이 "창고 끊김 13분"을 보려면 서버에 상태가 있어야 함 |
| 2.5 | 매장 감시 상태 조회: 카메라별 상태 + PC 온라인 여부 + 마지막 업로드/분석 시각 + 알림 지연(조각 길이) | 2c 상단, 모바일 2k 헤더 "감시 중 4/5대", 2m "PC 꺼짐 2시간" |
| 2.6 | 매장 설정 조회/수정: 조각 길이(30초/1분/5분, 전 카메라 공통) | 2b ③ 알림 빠르기, 2g |

## 3. 영상 조각 업로드  (PC 백그라운드 — 기존 `/v1/segments` 유지)
| # | 기능 | 비고 |
|---|---|---|
| 3.1 | 조각 업로드 (기존 SegmentMeta: 기기ID, 매장ID, 카메라ID, 시작/종료 시각, 시퀀스, 프로필, mp4) | 벽시계 정렬 경계 유지 → 카메라 간 동기 재생의 근거 |
| 3.2 | 업로드 실패 재시도 / 멱등 처리(같은 시퀀스 중복 무시) | 오프라인 스풀 후 밀린 순서대로 재전송 |
| 3.3 | 조각 원본 보관 7일, 조회: 특정 카메라 · 시각 범위의 조각 목록 + 재생 URL | 2f "◂ 더 이전 / 더 이후" 조각 단위 이동, 동시각 다른 카메라 |
| 3.4 | 라이브 미리보기(PC 로컬 RTSP → 스냅샷/스트림)는 서버 불필요 — PC 앱 내부 | 2b ②, 2c 격자. 모바일은 라이브 없음 |

## 4. 위험 이벤트  (핵심 — PC 2c/2d/2e/2f · 모바일 2i/2j/2k/2l)
| # | 기능 | 비고 |
|---|---|---|
| 4.1 | AI 분석 결과 → 이벤트 생성(서버 내부): 카메라, 시작/종료, 종류, 위험도, AI 설명(한글 문장 + 인상착의), 인물 바운딩박스(선택), 관련 조각ID, 클립 | 클립 = 위험 구간 ±여유 mp4 + 썸네일 |
| 4.2 | 이벤트 실시간 알림 채널 (PC): 웹소켓/SSE/롱폴 — 새 이벤트, 상태 변경, 카메라 상태 변경 | 2d 팝업 자동 띄우기, 2c 피드 갱신, 2c 배지 |
| 4.3 | 이벤트 목록 조회: 매장 · 날짜/기간 · 카메라 · 종류 · 위험도 · 상태 필터 + 페이지네이션, 최신순, 미확인 우선 | 2c 우측 피드(오늘), 2e 목록, 모바일 2k/2l |
| 4.4 | 하루 타임라인 데이터: 날짜의 카메라별 이벤트 구간 목록 + **영상 없음 구간**(카메라 끊김) | 2e 타임라인. 공백을 정직하게 보여주기 위해 결손 구간 필요 |
| 4.5 | 이벤트 상세: 클립 URL, 썸네일, 조각 목록, AI 설명, 상태, 메모, 처리 이력(누가/언제/어디서 확인) | 2d, 2f, 모바일 2j |
| 4.6 | 이벤트 상태 변경: 확인됨 / 오탐(+선택 사유) / 미확인 복귀 — 변경 시 4.2 채널·푸시로 양쪽 동기 | 2d/2f/2e/모바일 2j 버튼 |
| 4.7 | 이벤트 메모 저장 (112 접수번호, 피해액 등) | 2e/2f/모바일 |
| 4.8 | 동시각 다른 카메라: 이벤트 시각 기준으로 매장 내 모든 카메라의 조각/재생 URL 한 번에 | 2d "다른 카메라", 2f 4분할 |
| 4.9 | 미확인 카운트 (매장별, 오늘/전체) | 내비 배지, 모바일 탭 배지, 홈 "미확인 2" |
| 4.10 | 주간 요약: 기간 내 건수·오탐·신고 건수, 요일/시간대 반복 패턴 | 2e 하단, 모바일 2l 요약 카드 |
| 4.11 | 오탐 피드백은 AI 재학습 큐로 전달(내부) | 4.6에서 파생 |
