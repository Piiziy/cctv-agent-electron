# PC 앱 리디자인 — 디자인과 다른 점 · 검증 현황

`feat/scene-stealer-pc-redesign` 기준. 디자인 출처는 `design/씬스틸러 PC 앱.dc.html`(화면)과
`design/씬스틸러 디자인시스템.dc.html`(토큰·컴포넌트).

`handoff/CLAUDE-CODE-프롬프트.md` 의 완료 기준은 "디자인 HTML과 나란히 비교한 차이점 목록"이다.
아래 1~3절은 **의도적으로 다르게 한 것**이고, 4절은 두 화면을 같은 1440×900 으로 캡처해
나란히 놓고 본 결과다.

---

## 1. 일부러 다르게 한 것

모두 같은 원칙에서 나왔다 — **아직 사실이 아닌 것을 화면에 띄우지 않는다.**
없는 기능을 약속하는 버튼·문구는 사장님이 그걸 믿고 행동하게 만든다.

| 화면 | 디자인 | 구현 | 이유 |

## 2. 디자인에 없던 상태를 고른 것

값은 전부 디자인시스템 팔레트 안에서 골랐고, 코드에 이유를 한 줄씩 남겼다.

- **버튼 hover/active** — 같은 색 계열의 다음 단계(blue/700·800, error/700·800, gray/50·100).
  navy(`#14233D`)는 더 어두운 단계가 없어 밝기로 표현했다.
- **disabled** — 디자인의 `loading = gray/300` 과 같은 모양. 둘 다 "지금 누를 수 없다"는 뜻이다.
- **'서버 연결 끊김' 배너** — error/50 바탕 + error/main 글자 (위험 카드 배경과 같은 계열).
- **매장 선택 칩 드롭다운** — 카드 반경 + modal 그림자.
- **2e 표의 '미확인' 태그** — 디자인대로 빨간 계열. 디자인시스템 샘플의 파란 '미확인'과 다르다.

## 3. 실제로 동작을 바꾼 것 (디자인 밖)

- **2d 팝업은 위험도 '높음'과 응급(쓰러짐)에만 뜬다.** 보통·낮음은 피드와 배지로 쌓인다.
  계산대 PC 앞에서 '장시간 배회'마다 창이 튀어나오면 사장님이 알림을 무시하게 된다.
  2g 'PC 팝업 + 소리'로 끌 수 있다.
- **기본 알림 빠르기(조각 길이) 5분 → 1분.** 디자인 2b 의 기본값이자 백엔드 기본값.
  이미 설치된 PC 의 저장값은 바뀌지 않는다.
- **2d 경보음은 음원 파일 없이 WebAudio 로 만든다.**

## 4. 디자인과 나란히 비교

**방법.** 오프스크린 Electron 창(1440×900)에 디자인 `.dc.html` 의 2a–2g 화면과, 같은 크기로 띄운
렌더러(미리보기 mock 데이터)를 각각 캡처해 좌우로 붙여 봤다. 렌더러만 띄운 것이라 메인 프로세스
(카메라·ffmpeg·IPC)는 거치지 않았다.

**비교에서 찾아 고친 것.**

| 증상 | 원인 | 고친 곳 |
|---|---|---|
| primary 버튼(`확인했어요`·`확인`·`감시 시작`) 글자가 남색 바탕에 안 보임, 곳곳의 글자 크기가 기본값으로 돌아감, 끊긴 카메라 카드의 빨간 테두리가 안 보임 | tailwind-merge 가 토큰 이름(`text-body`, `shadow-card` …)을 몰라 '색'으로 보고 앞 클래스를 지웠다 | `lib/cn.ts` 에 토큰 이름 등록 + `tests/unit/cn.test.ts` |
| 모든 줄이 디자인보다 4~5px 높고, 2e 표 아래 요약·페이지 넘김과 메모 칸이 900px 밖으로 밀림 | 디자인은 line-height 가 없어 Pretendard normal(≈1.19), 앱은 Tailwind 기본 1.5 | `index.css` body · `tailwind.config.js` 글자 토큰을 1.2 로. 여러 줄 문단만 1.5 |
| 2e 목록에서 오탐이 확인됨 뒤로 몰림 (디자인은 시각순으로 섞임) | enum 선언 순서로 정렬 | 백엔드 `events.needs_review` 생성 컬럼으로 정렬, mock 도 같게 |
| 2f 조각 타임라인이 전부 '영상 없음' | mock 이벤트가 '오늘 14:32' 고정이라 오전에는 미래 | mock 시각을 '지금' 기준으로 |
| 2c 끊긴 카메라 칸 폭이 좁음 | 가로 폭 미지정 | `Live.tsx` |
| 2b 화질 카드가 고화질 먼저 | 카메라가 준 순서 그대로 | 표준(sub) 먼저 |
| 2g 카드 아래가 잘림 · 잠긴 토글이 흐리기만 함 · 시각 입력이 오전/오후 | flex 축소 · 상태 미정의 · `type=time` | `Settings.tsx`, `ui.tsx` Toggle |
| 2d AI 설명에 인상착의가 없음 | 팝업은 상황 설명만 썼다 (2f 는 붙여 씀) | `aiDescription()` 으로 둘을 같게 |
| 2c 피드 설명이 두 줄 | 디자인은 한 줄 요약 | 한 줄 말줄임 |
| 2e·2f 메모 칸이 낮음 | 디자인의 `min-height:64px` 는 padding 을 뺀 값(content-box) | `min-h-[88px]` |
| 2e 오른쪽 패널이 900px 을 13px 넘어 페이지가 스크롤됨 | 메모 칸 밑의 저장 상태 줄(20px) — 디자인에 없다 | 저장 상태를 칸 안 오른쪽 아래에 겹침 |

**비교해도 다른 것 (그대로 둠).**

- 2a 카드 위치가 디자인보다 아래 — QR 줄을 빼서(1절) 카드가 낮아졌고, 세로 가운데 정렬이다.
- 2c 격자 두 행 높이가 같음 — 디자인은 행 높이 지정이 없어 내용 따라 1행이 조금 낮게 그려졌다.
- 2b `확인` 버튼이 입력 칸과 같은 48px — 디자인은 `height:48px` 에 padding 이 더해져(content-box) 68px 로 그려졌다.
- 매장 이름·사용자·숫자·시각은 mock 데이터 차이.

**영상이 있는 상태는 비교하지 못했다.** mock 에는 실제 영상이 없어 2d 플레이어 조작 막대,
2f '같은 시각 다른 카메라' 썸네일은 '영상 없음' 상태로만 봤다.
